# Image processing pipeline
- `processor/core.py` owns PipelineContext (MutableMapping), ImageProcessor, registry and start_process. Filters/generators/mergers are separate modules; processor/types.py provides Alignment (and another Direction enum).
- Importing `processor` explicitly imports `processor.filters`, `processor.generators`, `processor.mergers` and registers pillow-heif. New modules must be added to that import list; this is not arbitrary filesystem plugin discovery.
- `ImageProcessor.__init_subclass__` wraps process for timing and constructs the subclass to register it under name(). Keep concrete subclasses constructible with zero arguments; registered names are external template identifiers.
- `PipelineContext` holds the supplied dictionary by reference; processing mutates it. Batch renders/parses template JSON per input file. Avoid sharing mutable node dictionaries across concurrent runs.
- Buffers are lists of Pillow images. Lazy file loading uses ImageOps.exif_transpose. start_process accepts input_path or initial_buffer; nonempty node lists are assumed.
- `all_buffer[0]` is the initial input; each processor appends its result, so output of zero-based node i is at i+1. Explicit `select` is parsed with json.loads and flattens the chosen buffer lists.
- Engine input_buffer has priority over select/previous output and sets buffer_loaded; it supplies independent source inputs for shortcut previews. Setting only buffer/buffer_loaded before the loop loses the intended input because update_buffer overwrites it.
- Without input_buffer/select: non-mergers receive previous output; mergers gather outputs since the previous implicit merger. Preserve these indexing semantics for existing templates.
- Nodes may override buffer_path to load an independent source. get_buffer only loads when buffer_loaded is false; update_buffer does not itself set that flag.
- EXIF is inserted into node contexts when an input file is supplied and the node lacks it. Output writing converts the final first image to RGB and uses configured quality/subsampling; return value is the final first Pillow image.
- `WatermarkFilter` uses `processor/watermark_1521.py` for automatic footer layout: reproduce the build1521 virtual 1000px footer, original font bounds, two columns, padding and logo placement, then scale the complete footer to the photo width. Default virtual ratios are 0.08 landscape and 0.13 portrait; `watermark_scale` changes the whole layout once. Explicit footer/text pixel constraints retain the legacy pixel path and fixed footer height takes precedence; keep edge anchors while scaling. Preserve center-logo containment, explicit `fit_center_columns`, styles, and EXIF orientation semantics.
- The build1521 text path shares the bounded thread-local bitmap cache with ordinary rich text, but uses a separate key and font-size-specific fallback. Keep mixed segments aligned and normalize fallback canvas height to glyph bounds without clipping, so a synthetic ℤ has the same row scale as native Z.
- `RichTextGenerator` caches final primary-font text bitmaps per worker thread with bounded pixel bytes and entry count. Include font version, text, height, weight, color and trim in the key, return copies, and leave fallback-font results uncached so system font changes take effect.
- Desktop raw-preview and metadata caches include source modification time and size. Templates referencing `files` additionally include batch-file modification times and sizes; templates without `files` must not traverse the batch for cache keys.
- `WatermarkSettings.protected_sources` is session-only and separate from Jinja `files` (selected inputs). Export protects the current source plus selected and all imported sources, including resolved path aliases and hardlinks, using a per-settings indexed snapshot; never persist this field.
- RichTextGenerator keeps the original drawing path when the configured font covers the whole text. core/font_fallback.py reads bounded cached OpenType cmap/OS/2 tables (including TTC) to choose per-run Windows symbol/CJK fonts only for missing glyphs. Match the primary font's weight for fallback strokes, align shared baselines, include actual glyph extents beyond font metrics, and preserve ordinary-text render parity. Do not replace Unicode symbols with visually similar ASCII or alter source fonts.
- Special case for missing U+2124 (ℤ): use the selected font's native Z outline and metrics with a proportional internal diagonal channel, preserving sans-serif terminals, cap height, width, weight and kerning. Never fall back to a foreign serif mathematical Z when native Z is available. Z is only a temporary glyph-layout surrogate; source/metadata/field values retain ℤ and the rendered glyph retains its double-struck feature. Leave genuine ℤ glyphs in explicitly selected fonts unchanged.
- `save_buffer` / `success` participate in node completion/debug flow; inspect their implementations before changing processing lifecycle.
- For caller/template context and batch event flow: `mem:core`. For processor/template coding representation: `mem:conventions`.
