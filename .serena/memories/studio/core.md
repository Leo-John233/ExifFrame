# Native photo workspace
- `main.py` is the Windows desktop entrypoint; `studio/` owns Qt widgets, file browsing, workers and template editing. Keep the entrypoint and package names; do not reintroduce the previous desktop_ui/desktop.py names.
- `studio/window.py` assembles actions, panes and signals. Library/import, preview scheduling, checked export, advanced editors and inspector-state bindings live in their respective `studio/workspace_*.py` modules. `studio/inspector.py` owns four sidebar views; `studio/inspector_footer.py` modifies editable regions through the same core.footer reader/writer as the advanced composer.
- `StudioState` owns the current photo, global template, ordered checked paths and canonical per-photo style/metadata. Choosing a card with an input selected changes only that photo. “Set as default” changes the workspace default. Current-only freezes an effective style; checked style sync copies style and template only. Checked EXIF sync merges explicitly selected fields. Session Location/UserComment feed footer location/comment; original files and persisted settings exclude session metadata and per-photo styles.
- Use effective per-photo settings for proxy and full-resolution renders. Export captures styles, template drafts, EXIF, checked-file context and all protected originals; each worker resolves the corresponding frozen settings. Opening the EXIF tab requests only the current photo after preview has had first access to metadata. Ordinary changes use the 80 ms debounce. Numeric gestures use the separate interactive pipeline described below. Keep the 250 ms idle gate for background scans.
- Localization lives in studio/i18n.py: tr/register_translations/bind/translator.language_changed. All fixed UI strings must have Chinese+English, including standard Qt buttons/calendars; never translate file names, camera brands or user edits. Language preference is separate ignored config/ui.json; switching locale must not invalidate previews or discard queues/drafts.
- View > About opens studio/about.py's modeless AboutDialog with the project TOML version, author Leo-John233 and public links. Keep its attribution consistent with README: semi-utils by leslievan is the development base, ExifEditor-GUI is a functional reference with an independent Qt implementation here, and ExifTool by Phil Harvey handles metadata. Do not infer an ExifFrame repository URL from the author handle; resolve the configured remote before linking the project repository.
- The main window uses one central canvas, a bottom horizontal filmstrip and a 340–348 px inspector. The four rail buttons open Presets, Frame, Text & Logo and EXIF. Preset filters and the two-column card grid share the actual preset registry. Use New for a blank editable preset or Save as preset for the current photo’s effective style. The default exchange format is a PNG preset card. The preview uses the target card’s settings and the current photo (or the bundled sample). Its ExifFramePreset iTXt payload contains a versioned, SHA-256 checked archive with the original Jinja source, display settings and image assets. JSON contains configuration and external path references. ZIP and .efstyle remain supported for import. Every card offers apply, duplicate, export and reveal; user cards also offer confirmed deletion, rename and overwrite. Keep shared assets and pending drafts when removing a preset.
- The sidebar owns current-photo editing. Ctrl+Shift+E opens Text & Logo, Ctrl+I opens EXIF and Ctrl+E opens the embedded source editor in Presets. Only the explicitly labelled EXIF file-copy tools open a separate window for lossless copies and migration. Older standalone editor classes remain available to existing callers.
- Photo queue check state, arrival order, canonical paths and the selected photo belong to FileBrowser. FilmBrowser displays that same item and selection model horizontally, without a second queue. Clicking the badge only changes export membership. Thumbnail work is restricted to horizontal viewport cells plus a small margin and shares the preview priority gate. On compact windows the filmstrip can fold automatically; the fold control and View menu can reopen it.
- ImageCanvas displays the original and logical output dimensions, physical zoom, Fit, 1:1 and hold-Space comparison. Accepted render results supply normalized slot bounds in the final output coordinate system. Clicks (not drags) on painted text or a logo select the matching sidebar slot. Original previews clear all hit targets. Keep the selection independent of draft/proxy/HD pixel density.
- Per-slot font, size, color, visibility, composition and per-character styling apply only to the chosen slot. The global scale/layout and advanced typography controls are separate. Resolve inherited descriptions from the accepted photo’s render metadata, including template expressions and automatic logos. Do not change a template by opening a page, changing language or inspecting an inherited value.
- ParameterHistory groups a slider gesture as one undo command. Commands restore exact per-photo overrides and the original checked sync targets, including inherited fields that were absent. Keep export settings, checked membership, language and theme outside parameter history.
- New-template default is the project example, even with no imported photos. core/sample_photo.py locates static/preview.jpg from the source root or portable app; scripts/build_preview_sample.py reproducibly extracts its clean 3:2 photo from static/standard1.jpeg and documents transcribed example EXIF. Never feed already-watermarked preset thumbnails back into rendering. Example preview snapshots clear user EXIF overrides and use only the sample as batch input; they never enqueue/export the sample as a user photo.
- studio/preview.py TemplatePreview is shared by creation, creation's advanced-source dialog and TemplateEditor. Copy real-photo settings/EXIF overrides/batch inputs, debounce edits, keep one active job plus the latest pending source, and discard stale results. Existing-template source previews follow the workspace's effective quick styles; new-template wizard previews use the template's own default styles. Propagate selection and session metadata changes to open source/wizard previews without replacing their photo or draft; sample snapshots stay isolated. Invalid source retains the last valid image. Only the central empty-state photo chooser is visible; switching an existing image is in its context menu. Long filename/status labels must ignore horizontal sizeHint to avoid expanding the window.
- Prefer photo width on narrow creation windows: compact header, bounded settings column, and zoom controls sharing a row with the filename. FooterPanel examples use the same exif/filename/file_dir/file_path/files context as the photo preview and refresh when the checked batch changes; metadata updates must not change drafts. Do not display static catalog examples once actual metadata exists. Sidebar TemplateThumbnail uses true heightForWidth and DPR-aware complete-image painting; a fixed wide/short QLabel frame or QLabel pixmap's fractional-DPR adjustment reintroduces aspect errors.
- Preview jobs/signals live under an application-owned pool, not the editing widget; shutdown only cancels future updates and must stay nonblocking. Accept/reject/close/handoff call shutdown; destruction also sets a cancellation event. This keeps running render tasks from referencing deleted Qt controls. MainWindow passes current photo/settings into creation/source editors; a wizard's own photo selection takes precedence over later main-window metadata callbacks.
- Photo information editing, migration and copy protection: `mem:metadata`.
- PySide6 UI runs offline. Dark uses a #181818 canvas, #232323 sidebar and #2C2C2C controls. The light theme uses the same layout and semantic contrast. Apply both themes to the active window. Theme preference lives in ignored config/theme.json, separate from language and rendering. Preserve the system/function icons and native Windows titlebar handling.
- UI font fallback explicitly includes Segoe UI Symbol and Cambria Math in both app font families and global QSS. Merely registering the system fonts does not fix Qt glyph fallback when mathematical symbols follow Chinese labels; do not remove the explicit family chain. Default-empty font databases (offscreen) require loading seguisym.ttf/cambria.ttc along with YaHei/Segoe UI.
- `core/desktop_service.py` adapts existing processor pipelines for previews/full-resolution exports, template CRUD and workspace settings. `WatermarkSettings` snapshots isolate background jobs from edits.
- Default use_template_styles=True preserves template styling; EXIF session overrides still apply. Quick style edits explicitly opt into overrides. `font_scale` is injected once as `watermark_scale` for footer nodes and scales standalone template text separately; explicit pixel sizes remain authoritative and a manual border is the final height. `border_override`, `background_override`, and `text_color_override` distinguish automatic template values from explicit user changes; migrate old nondefault saved values conservatively. Center-logo rendering contains the whole logo inside footer padding and honors canonical center_logo_height plus legacy center_height. The main centered-brand preset now includes camera/lens/exposure/date columns; 仅标识居中 is the separate compact logo-only preset. fit_center_columns reserves the center slot and shrinks long side text to avoid overlaps. `template_source` holds an unsaved preview draft and is never persisted in personal JSON.
- Shared template/input/output/overwrite/quality/subsampling settings use config/config.ini as authority; stale desktop JSON must not override them. Explicit workspace save synchronizes INI and ignored config/desktop.json; template source writes remain explicit. Export input_files contains the checked photos, or the current input photo when no boxes are checked. protected_sources covers every imported photo, including unchecked ones, and never enters Jinja. Neither list nor template drafts are persisted.
- Within input_dir, exports preserve relative directories and original stems; PNG remains PNG, JPEG/HEIC use JPEG. Existing output is skipped unless overwrite is enabled. Ad hoc photos outside the input root use *_watermarked names with unique numbering. Reject replacing source images or existing photos inside the input directory, and protect all batch/session source paths including same-file aliases.
- ExifTool discovery supports exiftool.exe and exiftool(-k).exe; UTF-8 stdin argument streams support Chinese paths and prevent -k pauses. JSON -l provides canonical tags plus description-derived legacy keys; retain Unicode, remove NUL terminators. Cache keys include tool path/mtime/size so installing the tool refreshes prior fallback metadata.
- Both template and quick-style previews render from oriented proxies (1800 px longest side). Preserve the original encoded dimensions in Jinja and scale spatial parameters together across inputs. Above 100% request a full-resolution preview; exports always use the full image. Track the original logical output size separately from the preview texture so a quality upgrade keeps the viewport in place. Use physical pixels for 1:1 on high-DPI screens. Keep batch dependency signatures, RGB/alpha conversion, EXIF and source protection consistent across quality levels.
- Qt object mutations stay on the GUI thread. Background image tasks signal detached QImage copies and ignore stale generations. Main-window export/import cancellation occurs between photos and app closing waits for those tasks; editing-window preview shutdown uses the independent lifetime described above. Batch export starts only after pending previews finish; it submits at most two photos only for fingerprint-verified built-in templates, falling back to one for modified/custom templates, unknown or low memory/size, or potentially colliding output paths. Cancellation stops new submissions but counts all already-started photos.
- Conda can provide an incompatible icuuc.dll with versioned symbols. main.prepare_windows_runtime preloads Windows System32 ICU for the current process before importing Qt. build_support/sitecustomize.py applies the same fix to PyInstaller child processes; do not replace DLLs in the user environment.
- For pipeline implementation invariants: `mem:processor/core`. For local run/build validation: `mem:suggested_commands` and `mem:task_completion`.
- Queue insertion is path-only. New items are unchecked, the first new input of a batch is highlighted, and later arrivals must respect manual navigation. Restore checks by path only on same-directory refresh. Export checked inputs in insertion order or, with no checks, the current input photo; preserve every imported source in the overwrite guard.
- Thumbnail decoding uses a single low-priority worker and a viewport-sized candidate list with a small buffer. Invalidate pending batches on scroll, refresh or removal; do not prefetch all sources or EXIF. Pause scanning and thumbnails across preview debounce, render and HD/compare requests until 250 ms of idle time. A preview may supply dimensions before the thumbnail is ready.
- `studio/controls.py` owns CameraRawSlider, ColorProperty, CollapsibleSection and the app-wide wheel guard. Sliders use a muted light fill to the left, a dark remainder, an unobtrusive numeric editor and a compact physical or percentage unit. Both slot colors and frame materials use a checker-backed swatch with an inherited value and a reset action. User gestures emit live values followed by a commit. Programmatic synchronization does not begin a gesture. Forward wheels from parameter editors to their containing scroll area and preserve canvas zoom and normal list scrolling.
- During parameter gestures, display an in-memory bilinear 900-pixel draft with one active render and one replaceable pending value. Throttle submissions at 33 ms and cancel by photo/template generation. Commit after about 120 ms at 1800 pixels with Lanczos, or at full resolution when zoomed above 100%. Keep logical dimensions and the last visible image stable during the upgrade.
